# مرز دادهٔ TradingView و پایش معامله — ارزیابی صنعتی

## سؤال: آیا می‌شود از خود TradingView استریم گرفت؟

**برای نمایش بله؛ برای تیک خروج معامله در اپ فعلی نه.** [FAQ رسمی ویجت‌ها](https://www.tradingview.com/widget-docs/faq/data/) می‌گوید ویجت Forex/crypto را می‌تواند برخط *نمایش* دهد، اما API خروج داده یا مقادیر اندیکاتور ندارد و امکان تزریق دادهٔ خودمان به ویجت نیست. تنها ویجت iframe اپ (`TradingViewEmbed.kt`) به همین خانواده تعلق دارد. [Datafeed API در Advanced Charts](https://www.tradingview.com/charting-library-docs/latest/connecting_data/) جهت معکوس دارد: خودِ برنامه باید تاریخچه و WebSocket بازار را برای چارت فراهم کند؛ [subscribeBars](https://www.tradingview.com/charting-library-docs/latest/connecting_data/datafeed-api/datafeed-subscriptions/) خروجی OHLCV از datafeed ما به چارت است، نه جریان خام تیک TradingView به موتور. جایگزین‌کردن iframe موجود با Charting Library هم مجوز/دسترسی جداگانه و تغییر خواستهٔ «یک ویجت TradingView» را لازم دارد و به‌خودی‌خود فید نمی‌آورد.

[بند ۳ شرایط رسمی TradingView](https://www.tradingview.com/policies/) استفادهٔ داده/چارت/هشدار آن برای تصمیم خودکار، ارجاع قیمت معامله و مدیریت ریسکِ غیرنمایشی را ممنوع می‌کند؛ FAQ نیز صریحاً می‌گوید API خروج داده ندارند. استخراج WebSocket داخلی iframe، تقلید کلاینت خصوصی یا استفاده از endpoint نامستند scanner برای خروج/ورود روش قانونی/پایدار این محصول نیست. **چارت TradingView صرفاً نمایش است**؛ قیمت نمودار Binance/OANDA نباید قیمت تسویهٔ پوزیشن Nobitex شود.

## مقایسه و انتخابِ قابل اجرا

| نامزد | دادهٔ مناسب برای خروج Nobitex؟ | بازیابی/وابستگی | انتخاب |
|---|---|---|---|
| iframe/widget TradingView | خیر؛ API خروج تیک ندارد و مجوز display-only است | مرورگر و طرف سوم، بدون checkpoint معامله | فقط نمایش؛ دست‌نخورده |
| Advanced Charts با datafeed اختصاصی | داده را خودمان باید تأمین کنیم؛ `subscribeBars` بار OHLCV است | نیاز به مجوز/دسترسی کتابخانه و فید بیرونی | تعویض ویجت مسئلهٔ دریافت تیک را حل نمی‌کند |
| scanner نامستند TradingView | خیر؛ بدون قرارداد API مجاز/زمان و venue قابل اتکا | شکننده و استفادهٔ غیرنمایشی ممنوع | از Watch/تصمیمات برنامه حذف شد |
| WebSocket مستند Nobitex، `public:trades-SYMBOL` | بله؛ همان بازار USDT تاریخچه و ورود | SDK رسمی Centrifugo؛ recovery فقط اگر کانال و سرور پشتیبانی کنند | مسیر اصلی پوزیشن باز |
| REST مستند Nobitex `/v2/trades/SYMBOL` | بله، ولی صفحهٔ اخیر بدون شناسه | بدون بازیابی کاملِ قطع/rollover | bootstrap/پشتیبان و دیده‌بانِ با سهمیه |
| Binance aggTrades با ID | نه برای پوزیشن Nobitex | ID/fromId و replay بهتر، ولی venue متفاوت و دسترسی منطقه‌ای متغیر | فقط با مهاجرت کامل تاریخچه/ورود/خروج یک پوزیشن تازه |
| Forex/طلا و سایر بازارها | quote snapshot/بازار غیرمتمرکز، نه همهٔ executionها | نیازمند قرارداد فید/مجوز اختصاصی همان venue | ادعای پایش «هر تیک» نمی‌کنیم |

منبع کانال عمومی: [مستند رسمی نوبیتکس](https://github.com/nobitex/docs-api/blob/d5330f026fda422f4f7c4ac3b8f1c8e9be3ee681/source/includes/_websocket.md#public-trades). اجرای فید/بازیابی و محدودیت گوشی: [طرح پوزیشن باز](OPEN_POSITION_TICK_DESIGN_FA.md).

## تغییر اجرایی و آزمون

- SourceCatalog دیگر `tradingview_scanner` یا درخواست به `scanner.tradingview.com` ندارد. نگاشت TradingView فقط برای **یک چارت نمایشی** نگه داشته می‌شود. تنظیمات قدیمی دیده‌بان که فقط این منبع را انتخاب کرده بودند به منبع موجود همان نماد مهاجرت می‌کنند؛ دادهٔ کش‌شدهٔ منبع حذف‌شده دوباره قیمت تازه نمی‌شود.
- دیده‌بان USDT از معاملات زمان‌دار عمومی Nobitex (همان منبعِ پوزیشن باز) با بودجهٔ مشترک و حداکثر یک دور/دقیقه برای شش جفت پیش‌فرض تغذیه می‌شود. در خطای ناشر/سهمیه، دادهٔ قبلی با زمان اولیه و وضعیت خطا باقی می‌ماند؛ سهمیهٔ محفوظِ پوزیشن باز مصرف نمی‌شود. دیده‌بان FX تک‌منبعی را دومنبعی تأییدشده جا نمی‌زند. قیمت OANDA/Binance چارت **هیچ‌وقت** به سفارش/ژورنال وارد نمی‌شود.
- در stream، offset بازیابی‌پذیرِ ناشر ترتیب معتبر است، نه لزوماً میلی‌ثانیهٔ اجرای معامله. حالت «بازیابی سرور اعلام شد» از حالت «قابلیت بازیابی تأیید نشده» در ژورنال متمایز است. نبود offset، پرش، کهنگی و handoff REST همچنان گسست را ثبت می‌کند؛ replay با زمان جدید جعل نمی‌شود.
- تست‌های JVM مرز ویجت، مهاجرت تنظیمات قدیمی، شناسهٔ بازار USDT، ترتیب offset و قراردادهای موجود ژورنال را می‌سنجند. بدون آزمون اینترنت/گوشیِ واقعی یا توافق مجوز داده، تضمین ۲۴ساعته و پوشش تک‌تک تیک‌ها اعلام نمی‌شود.

## مسیر بایگانی مستقل از عمر گوشی (اختیاری؛ پس از استقرار روی سرور خودتان)

ماژول [`tick-archive/`](../tick-archive/README.md) تیک‌های عمومی **همان نوبیتکس** را از WebSocket مستند با SDK رسمی Centrifugo به SQLite با نوشتن پایدار می‌برد؛ `seq` داخلی، رکورد گسست و API صفحه‌بندی‌شدهٔ HTTPS/Bearer دارد. نسخهٔ Android می‌تواند از تنظیمات، نشانی سرور خودتان و کلید خواندن را فقط روی گوشی ذخیره کند؛ **تنها پوزیشن‌های کاغذی جدید** پس از فعال‌سازی از این مسیر استفاده می‌کنند. هنگام اتصال دوباره، ژورنال ردیف‌ها را به‌ترتیب `seq` بازپخش می‌کند و همان لحظهٔ تسویه/انتقال حدضرر، cursor را اتمیک ثبت می‌کند. سایر منابع نمی‌توانند روی یک پوزیشنِ بایگانی‌شده مجدداً تسویه انجام دهند. سرویس برای بازارهای غیرکریپتو یا صرافی دیگر منبع خروج نیست.

سرور **هیچ دادهٔ پوزیشن/کلید معامله** دریافت نمی‌کند، پس وقتی گوشی خاموش است فقط فید را ذخیره می‌کند؛ محاسبهٔ خروج و اعلان ژورنال بعد از اتصال گوشی انجام می‌شود، نه در همان لحظهٔ خاموشی. برای تسویه و هشدار واقعیِ سمت سرور باید زیرساخت همیشه‌روشن، اجازهٔ صریح انتقال پوزیشن و مسیر امن همگام‌سازی فراهم شود. هیچ بک‌تست یا حالت آموزشی داخل اپ اضافه نشده است. قطع upstream، وقفهٔ استقرار یا نبود پشتیبانی replay از طرف صرافی با **gap** ثبت می‌شود و حتی داشتن سرور دلیل پوشش تضمینی تک‌تک معاملات نیست.
