# کارنامهٔ کلی ژورنال — طراحی جدید (نسخهٔ ۳.۹.۲۸)

این سند توضیح می‌دهد «کارنامهٔ کلی» صفحهٔ ژورنال بر چه پایه‌ای بازطراحی شد و هر عدد از کجا می‌آید.

## ۱. مشکل نسخهٔ قبل

کارنامهٔ قبلی یک ردیف عدد پراکنده بود: سود خالص، نرخ برد، پرافیت‌فاکتور و SQN.
این اعداد سه ضعف ساختاری داشتند:

1. **هر کدام در جای دیگری از UI دوباره محاسبه می‌شدند** (ژورنال، tear-sheet، کارت استراتژی، PDF) و
   می‌توانستند با هم اختلاف پیدا کنند.
2. **ریسک دیده نمی‌شد:** حداکثر افت سرمایه، فاکتور بازیابی، بدترین معامله و توالی باخت — که
   تصمیم واقعی روی آن‌ها گرفته می‌شود — در کارنامه نبود.
3. **هیچ تفکیکی نبود که بگوید پول کجا درمی‌آید:** دستهٔ بازار (رمزارز/طلا/فارکس/شاخص)، نماد،
   تایم‌فریم یا جهت معامله.

## ۲. ساختار جدید

منبع واحد اعداد، موتور خالص `core/TradingPerformanceAnalytics.kt` است:

```kotlin
TradingPerformanceAnalytics.analyze(
    trades = filteredTrades,        // همان لیست فیلترشدهٔ ژورنال
    nowMs = System.currentTimeMillis(),
    startingBalanceUsd = settings.initialCapital,
)
```

خروجی `PerformanceReport` است و UI (`ui/components/JournalPerformanceDashboard.kt`) فقط آن را
نمایش می‌دهد؛ هیچ محاسبهٔ موازی در Compose نیست.

کارنامه از بالا به پایین چهار پرسش را پاسخ می‌دهد:

| بخش | پرسش | شاخص‌ها |
|---|---|---|
| سرصفحه | آیا سیستم سودده است؟ | سود/زیان خالص، حکم سلامت (🟢/🟡/🔴)، خط خلاصهٔ فارسی |
| منحنی سرمایه | مسیر سرمایه چگونه بوده؟ | منحنی سود انباشته + خط سربه‌سر + حداکثر افت |
| عددهای تصمیم‌ساز | ریسک چقدر است؟ | مجموع R، میانگین R، امید ریاضی، PF، نرخ برد، پرداخت/ریسک، حداکثر افت درصدی، فاکتور بازیابی، بهترین/بدترین معامله، توالی فعلی، ۷/۳۰ روز، میانگین نگه‌داری، بیشترین باخت پیاپی |
| توزیع R | کیفیت خروج چگونه است؟ | ۶ سبد: `≤ -1R`، `-1R…0`، `0…1R`، `1R…2R`، `2R…3R`، `≥ 3R` |
| جدول‌های تفکیک | کجا پول درمی‌آید؟ | بر اساس دستهٔ بازار، نماد (۶ نماد برتر)، تایم‌فریم و جهت |

## ۳. تعریف دقیق شاخص‌ها

- **مجموع R:** جمع `rMultiple` همهٔ معامله‌های بسته. اگر معامله‌ای `rMultiple` نداشته باشد، از
  `سود ÷ ریسک ثابت` (با کف پیش‌فرض ۵ دلار) محاسبه می‌شود تا هیچ معامله‌ای از کارنامه حذف نشود.
- **امید ریاضی (Expectancy):** میانگین سود هر معامله به دلار = `(نرخ برد × میانگین سود) − (نرخ باخت × میانگین ضرر)`.
- **پرداخت/ریسک (Payoff):** `میانگین سود ÷ میانگین ضرر`. مقدار `1 : 1.5` یعنی به‌طور میانگین
  هر برد یک‌ونیم برابر هر باخت است.
- **حداکثر افت سرمایه (Max DD):** بزرگ‌ترین فاصلهٔ منحنی سرمایه از سقف قبلی خودش؛ هم به دلار و
  هم به درصد سقف گزارش می‌شود.
- **فاکتور بازیابی:** `سود خالص ÷ حداکثر افت`. زیر ۱ یعنی سیستم هنوز افت خودش را جبران نکرده.
- **توالی فعلی:** مثبت = برد پیاپی، منفی = باخت پیاپی، صفر = آخرین معامله سربه‌سر.

## ۴. حکم سلامت (Health Verdict)

سه حالت دارد و روی سرصفحه به رنگ سبز/طلایی/قرمز نمایش داده می‌شود:

- 🟢 **GOOD** — سودده با پرافیت‌فاکتور و نرخ برد قابل قبول و افت سرمایه مهارشده.
- 🟡 **WARN** — نزدیک مرز سربه‌سر، یا سودده ولی با افت/توالی باخت نگران‌کننده.
- 🔴 **BAD** — زیان‌ده یا پرافیت‌فاکتور زیر ۱.

این حکم فقط توصیف است و هیچ‌جا Entry را مسدود نمی‌کند؛ گیت اجرایی همان «قانون دوشرطی» هوش عصبی
است که در `docs/NEURAL_LEARNING_LEDGER_FA.md` توضیح داده شده.
