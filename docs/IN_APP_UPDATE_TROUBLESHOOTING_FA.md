# چرا بروزرسانی از داخل اپ کار نمی‌کرد و چه چیزی اصلاح شد

## علت‌های واقعی (اندازه‌گیری‌شده، نه حدس)

| علت | توضیح |
|---|---|
| ۱. manifest قدیمی روی شاخهٔ پیش‌فرض | `update/aurum-edge.json` روی `main` هنوز `versionCode=353 / v1.3.0` بود. CI فایل تازه را می‌ساخت اما هرگز برنمی‌گرداند؛ پس کانال manifest برای هر نصب ۶۷۲ «چیزی جدید» نداشت. |
| ۲. قفل شدن سهمیهٔ GitHub API | بررسی خودکار در هر اجرای برنامه انجام می‌شد. GitHub برای هر IP عمومی ۶۰ درخواست/ساعت بی‌توکن می‌دهد و IP شبکهٔ موبایل مشترک است؛ نتیجه HTTP 403 و پیام مبهم «بررسی انجام نشد». |
| ۳. ۱۰ درخواست اضافی در هر بررسی | برای هر Release یک sidecar از میزبان `release-assets` گرفته می‌شد؛ روی شبکهٔ فیلترشده کند/ناموفق. |
| ۴. پیام‌های بی‌جزئیات | خطاها می‌گفتند «پاسخ بروزرسانی معتبر نیست (403)» بدون نام میزبان و بدون تفکیک سهمیه/فیلترینگ. |
| ۵. انتظار نادرست | اگر نصب کنونی همان کد ۶۷۲ باشد، «نسخهٔ جدیدی نیست» **رفتار درست** است؛ Android اجازهٔ نصب بی‌صدا نمی‌دهد و آپدیتر فقط APK منتشرشده با **کد بالاتر** را پیشنهاد می‌کند. |

بررسی زنده (۲۰۲۶-۱۰-۱۵): برای نصب ۶۷۱ نسخهٔ `v2.0.0` (کد ۶۷۲) با امضای پین‌شده پیدا می‌شود؛ برای نصب ۶۷۲ هیچ نسخهٔ جدیدتری وجود ندارد.
ابزار: `python3 tools/diagnose_in_app_update.py --installed-code 671`.

## اصلاحات

- **ترتیب کانال‌ها:** اپ اول `releases/latest/download/aurum-edge.json` (کنار خود APK در Release) را می‌خواند، سپس manifest شاخهٔ `main` را؛ پس PR ادغام‌نشده یا شاخهٔ قدیمی دیگر می‌تواند بروزرسانی را پنهان کند.
- **صرفه‌جویی در سهمیه:** بررسی خودکار حداکثر هر ۱۵ دقیقه یک‌بار (`MIN_AUTO_CHECK_INTERVAL_MS`)؛ دکمهٔ «بررسی نسخه جدید» همیشه فوری است.
- **یک درخواست به‌جای ده:** فقط sidecar جدیدترین Release با asset معتبر گرفته می‌شود (لیست GitHub از جدید به قدیم است).
- **تشخیص شفاف:** پیام‌ها نام میزبان و نوع خطا (سهمیه/فیلتر/۴۰۴/۵xx/قطع اتصال) را می‌گویند و `State.diagnostics` نتیجهٔ هر کانال را در تب بروزرسانی نشان می‌دهد.
- **گیت CI:** مرحلهٔ «Verify default-branch manifest points at the newest release» اگر manifest از جدیدترین Release عقب بماند، اجرا را می‌شکند.
- **فایل manifest:** `update/aurum-edge.json` به مقادیر `v2.0.0 (672)` به‌روز شد (هش/حجم/گواهی همان Release).

## انتشار یک بروزرسانی واقعی (نیازمندی باقی‌مانده)

APK بزرگ‌تر از کد نصب‌شده باید در Release عمومی منتشر شود. مسیر دستی:

```bash
gh workflow run main.yml --ref <branch> -f publish_release=true -f version_name=2.0.1 -f version_code=673
```

گیت‌های CI پیش از انتشار: `applicationId`, SHA-256, حجم، گواهی امضا، افزایش `versionCode` و سلامت ZIP. تگ موجود بازنویسی نمی‌شود.

## گیت‌های آپدیتر روی گوشی (بدون تغییر، همه باید رد شوند)

نام asset/URL مورد اعتماد · HTTPS · `versionCode` بزرگ‌تر از نصب · تطابق SHA-256 و حجم · خوانا بودن گواهی اپ دانلودی · برابری امضای APK دانلودی با **نصب همین گوشی** · اجازهٔ «نصب از این برنامه» · تأیید نهایی نصاب Android.

آزمون‌های خودکار: `UpdaterChannelOutcomeTest` (سناریوهای بالا با HTTP ساختگی، بدون شبکه/کلید) و `UpdaterDiscoveryTest`.
