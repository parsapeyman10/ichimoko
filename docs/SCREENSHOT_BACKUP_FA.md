# بکاپ اسکرین‌شات‌های آرشیو — تب آپدیت

این سند توضیح می‌دهد کارت «بکاپ اسکرین‌شات‌های آرشیو» در **تب آپدیت** چه می‌کند، فایل‌ها کجا
ذخیره می‌شوند و اگر عددی با انتظار شما نخواند کدام تابع را باید بررسی کنید.

---

## ۱) این بکاپ چیست؟

اپ از هر معامله دو تصویر می‌سازد:

| تصویر | لحظه | چه چیزی در آن است |
|---|---|---|
| `OPEN` | همان لحظهٔ باز شدن پوزیشن | کندل‌ها، کومو، آیندهٔ ۲۶ کندلی، باکس SL/TP، شروط ۱۶گانهٔ ایچیموکو |
| `CLOSE` | لحظهٔ بسته شدن (TP/SL/دستی) | همان چارت + قیمت خروج، دلیل خروج و سود/زیان تحقق‌یافته |

هر تصویر یک **دادهٔ خواندنی داخل خودش** دارد (بلوک JSON نشان‌دار)، بنابراین فایل تصویر تنها هم
قابل بازخوانی است. از نسخهٔ ۳.۹.۴۸ به بعد، تصاویر تازه فقط در فضای خصوصی اپ نگه داشته می‌شوند:

- آرشیو داخلی اپ: `filesDir/trade_snapshots_v1/*.webp` + فهرست `trade_snapshots_index_v1.json`
- از کارت «آرشیو تصاویر معاملات» داخل Aurum Edge باز می‌شوند؛ ساخت تصویر هیچ فایلی به گالری یا Downloads اضافه نمی‌کند.

تصاویر عمومیِ ساخته‌شده در نسخه‌های قدیمی حذف نمی‌شوند تا عکس‌های کاربر ناخواسته دست‌کاری نشوند.
کارت تب آپدیت، آرشیو داخلی را بنا به درخواست کاربر در **یک فایل ZIP/PDF** خروجی می‌گیرد تا
بتوان آن را با Share Sheet به Google Drive یا هر مقصد دیگری فرستاد.

## ۲) دکمه‌ها

| دکمه | کار | نتیجه |
|---|---|---|
| 💾 ذخیره در دانلود | ساخت ZIP از همهٔ تصاویر آرشیو و کپی آن در حافظهٔ گوشی | `Download/AurumEdge/Screenshots/AurumScreenshots_<yyyyMMdd_HHmmss>.zip` |
| 📤 ارسال | همان ZIP از طریق Share Sheet اندروید | تلگرام، واتساپ، ایمیل، گوگل‌درایو و … |
| 📥 بازخوانی از فایل ZIP | خواندن تصاویر و فهرست از یک ZIP و **ادغام** با آرشیو فعلی | آرشیو فعلی پاک نمی‌شود |
| 🔄 تازه‌سازی آمار | خواندن دوبارهٔ تعداد و حجم تصاویر | عددهای کارت به‌روز می‌شوند |

## ۳) عددهای کارت از کجا می‌آید؟

| کاشی | منبع | تابع |
|---|---|---|
| تعداد تصویر | شمارش فایل‌های تصویری داخل `trade_snapshots_v1` | `TradeSnapshotArchiveManager.archiveBasket` |
| حجم تصاویر | جمع خام حجم همان فایل‌ها (قبل از فشرده‌سازی ZIP) | همان |
| رکورد فهرست | تعداد رکوردهای ایندکس | همان |
| آخرین بکاپ | نام و حجم آخرین ZIP ساخته‌شده در همین نشست | `AurumViewModel.screenshotBackup` |

## ۴) داخل فایل ZIP چه هست؟

```
AurumScreenshots_20261101_061500.zip
├── screenshots/            ← همهٔ تصاویر WebP (نام هر فایل: شمارهٔ معامله، فاز، نماد، تایم‌فریم، زمان)
├── trade_snapshots_index_v1.json   ← فهرست کامل رکوردها (قیمت ورود، SL، TP، نتیجه، دلیل خروج)
└── README_FA.txt           ← تاریخ ساخت، تعداد تصویر، نسخهٔ اپ و روش بازگردانی
```

## ۵) مسیر کد

| کار | فایل و تابع |
|---|---|
| شمارش آرشیو | `data/TradeSnapshotArchiveManager.kt` · `archiveBasket` |
| ساخت ZIP | همان · `buildSnapshotZipBundle` (خروجی در `cacheDir/exports`) |
| ذخیره در دانلود | همان · `saveSnapshotZipToDownloads` (اندروید ۱۰+ با MediaStore، پایین‌تر با مسیر عمومی) |
| اشتراک‌گذاری | همان · `shareSnapshotZip` (FileProvider با authority `<packageName>.updateprovider`) |
| بازخوانی ZIP | همان · `importSnapshotZip` |
| دکمه‌ها و وضعیت | `ui/shell/AurumViewModel.kt` · `saveScreenshotBackupToDownloads` / `shareScreenshotBackup` / `restoreScreenshotBackupFromZip` / `refreshScreenshotBackupStats` |
| کارت رابط کاربری | `ui/tabs/update/UpdateScreen.kt` · «بکاپ اسکرین‌شات‌های آرشیو» |

## ۶) نکته‌های ایمنی

- این کارت **هیچ تصویری را پاک نمی‌کند**؛ فقط می‌خواند و کپی می‌سازد.
- «بازخوانی از فایل ZIP» آرشیو فعلی را پاک نمی‌کند و فقط رکوردهای جدید را اضافه می‌کند
  (کلید یکتا: `tradeId + snapshotPhase`).
- محدودیت حافظه با `AppResourceGovernor` مدیریت می‌شود؛ اگر آرشیو پر شود، قدیمی‌ترین
  تصاویر حذف می‌شوند (نه با این بکاپ، بلکه با چرخهٔ نگهداری خودکار اپ). برای همین اگر
  می‌خواهید تاریخچهٔ کامل بماند، ZIP را جای دیگری نگه دارید.
- اجازهٔ حافظه اضافه‌ای لازم نیست: روی اندروید ۱۰ و بالاتر با MediaStore داخل `Download`
  نوشته می‌شود و روی نسخه‌های قدیمی‌تر در همان مسیر عمومی.
