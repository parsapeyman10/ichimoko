## کنترل‌های پیش از انتشار

Workflow علاوه بر تست‌های اندروید و بررسی امضای قبلی، خودِ APK ساخته‌شده و آخرین APK
عمومی را با `apksigner` و `aapt` مقایسه می‌کند. اسکریپت
`tools/verify_apk_upgrade.py` انتشار ناسازگار را متوقف می‌کند:

- اعتبار امضای محتوای هر دو APK و برابری **مجموعهٔ کامل امضاکنندگان** با گواهی بالا؛
- شناسهٔ بستهٔ `com.aurum.edge`، تطابق نسخهٔ داخل APK با متادیتا و افزایش اکید versionCode؛
- APK مستقل، غیر debug، غیر testOnly؛ نه APK مربوط به split یا بستهٔ debug جداگانه؛
- افزایش‌نیافتن حداقل اندروید از نسخهٔ قبل (فعلاً API 26 / Android 8) و targetSdk=35؛
- حفظ معماری‌های قبلی و ARM64/ARMv7، وجود `libtor.so` برای هر دو معماری؛
- وجود مجوز درخواست نصب برای به‌روزرسانی‌های بعدی، سلامت ZIP و حجم کمتر از سقف ۲۰۰ MiB آپدیتر؛
- برابری SHA-256، حجم و نسخهٔ واقعی فایل با JSON کنار APK.

پیکربندی فعلی FileProvider بررسی شده است: provider غیر exported با نام
`${applicationId}.updateprovider`، مسیر محدود `cache/updates/` و دسترسی موقت خواندن URI
برای نصاب. `REQUEST_INSTALL_PACKAGES` برقرار است و پس از بازگشت از صفحهٔ مجوز نصب،
فرایند با تأیید Android ادامه پیدا می‌کند. این کنترل‌ها جای آزمایش نصب روی گوشی واقعی را نمی‌گیرند.

هیچ keystore تازه‌ای ساخته نمی‌شود. اگر کلید قبلی در secrets یا cache معتبر موجود نباشد،
ساخت انتشار متوقف می‌شود؛ راه‌حل، بازیابی **همان کلید** است، نه تعویض امضا یا حذف نصب.

## تحویل عمومی به آپدیتر قدیمی

این شاخه فقط با اجرای دستی workflow و `publish_release=true`، برای همین نسخهٔ ۱.۳.۵۰/۶۶۶
مجاز به انتشار است؛ push معمولی و PR صرفاً اعتبارسنجی هستند:

```bash
gh workflow run main.yml --ref arena/3d998929-ichimoko -f publish_release=true
```

Workflow ابتدا draft می‌سازد، APK و JSON و checksum و `upgrade-compatibility.json` را آپلود
می‌کند و سپس آن را عمومی می‌کند. تگ از قبل موجود بازنویسی نمی‌شود. بعد از انتشار، فهرست
Releases و دانلود **بدون توکن** APK/JSON بررسی شده و hash و حجم دانلود دوباره تطبیق داده می‌شوند.

آپدیتر نسخهٔ ۱.۳.۴۹ علاوه بر manifest قدیمی شاخهٔ main، ده Release عمومی آخر را بررسی می‌کند.
بنابراین قدیمی‌ماندن manifest روی main یا ادغام‌نشدن PR، به‌تنهایی مانع دریافت Release عمومی نیست.
تست `UpdaterDiscoveryTest` با پاسخ‌های مصنوعی، manifest قدیمی/ناموفق، متادیتای دارای فیلدهای
اضافی، رد نسخهٔ هم‌کد و رد draft/prerelease را بررسی می‌کند؛ هیچ حساب یا کلید واقعی استفاده نمی‌شود.
