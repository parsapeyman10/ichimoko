# قاعدهٔ شماره‌گذاری نسخه‌ها (از ۳.۱۲.۰۰۰۱ به بعد)

این قاعده را خودِ کاربر تعیین کرده است (پیام ۱۸ نوامبر):

> «ورژن بعدی ۳.۱۲.xxxx باید تا ۱۰۰۰۰ تا ورژن بری جلو، بعد ۳.۱۳.۰۰۰۱ بدی»

## قالب

```
3.12.0001
  │  │   └── شمارهٔ چهاررقمیِ انتشار داخل همین نسخهٔ مینور (۰۰۰۱ تا ۱۰۰۰۰)
  │  └────── نسخهٔ مینور (۳.۱۲ → ۳.۱۳ → ۳.۱۴ …)
  └───────── نسخهٔ ماژور
```

- **مینور ۳.۱۲**: از `3.12.0001` شروع و تا `3.12.10000` ادامه پیدا می‌کند.
- بعد از `3.12.10000`، مینور به `3.13` می‌رود و دوباره از `3.13.0001` شروع می‌شود.
- صفرهای ابتدایی حذف نمی‌شوند؛ `3.12.0001` نوشته می‌شود، نه `3.12.1`.
- `versionCode` مستقل از این قالب است و در هر انتشار **دقیقاً یک واحد** بالا می‌رود
  (`812`، `813`، …). اندروید و به‌روزرسان فقط `versionCode` را مقایسه می‌کنند، پس هیچ‌وقت
  عقب برنمی‌گردد.
- تگ گیت و نام فایل انتشار: `v<versionName>` → مثلاً `v3.12.0001` و
  `AurumEdge-v3.12.0001.apk`.

## مثال زنجیره

| انتشار | versionName | versionCode |
|---|---|---|
| قبل از این قاعده | `3.12.0` | 811 |
| اولین نسخهٔ قاعدهٔ نو | `3.12.0001` | 812 |
| بعدی | `3.12.0002` | 813 |
| … | `3.12.9999` | … |
| آخرین نسخهٔ مینور ۳.۱۲ | `3.12.10000` | … |
| اولین نسخهٔ مینور ۳.۱۳ | `3.13.0001` | +۱ |

## کارهای هر انتشار

1. `android/app/build.gradle.kts`: `versionCode += 1` و `versionName` طبق قاعدهٔ بالا.
2. ورودی تازه در بالای `CHANGELOG_FA.md`.
3. انتشار با ورک‌فلو: `publish_release=true`، `version_name` و `version_code` همان دو عدد.
4. هم‌گام‌سازی `update/aurum-edge.json` با مانیفست شاخهٔ `main` (کار خود ورک‌فلو).
