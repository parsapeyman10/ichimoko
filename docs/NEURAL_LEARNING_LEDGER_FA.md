## ۱. مشکل: عدد «لرن‌شده» با تعداد تریدهای واقعی یکی نبود

شبکهٔ عصبی خودآموز (`NeuralSelfLearningEngine`) با هر معاملهٔ بسته‌شده آموزش می‌بیند و یک شمارندهٔ
`totalLearnedTrades` را نشان می‌دهد. این شمارنده سه اشکال ساختاری داشت:

### باگ ۱ — تشخیص «قبلاً یاد گرفته‌ام؟» روی حافظهٔ ۳۲۰تایی
```kotlin
// کد قبلی
val seenIds = persistedState.replayBuffer.map { it.tradeId }.toSet()   // فقط ۳۲۰ نمونه می‌ماند
val unseen = validClosed.filterNot { it.id in seenIds }
```
به‌محض اینکه تعداد معامله‌ها از ۳۲۰ بیشتر می‌شد، شناسهٔ معامله‌های قدیمی از `replayBuffer` بیرون
می‌افتاد و در همگام‌سازی بعدی «تازه» تلقی می‌شد. `syncWithClosedJournalTrades` با هر تغییر ژورنال
(و در بدو ورود به اپ) صدا زده می‌شود؛ نتیجه: **آموزش تکراری همان معامله‌ها** و تورم شمارنده.

### باگ ۲ — شمارنده یک عدد مستقل بود، نه یک نتیجهٔ قابل بازبینی
`totalLearnedTrades = totalLearnedTrades + 1` هیچ ارتباطی با دفتر معامله‌های یکتا نداشت. اگر عدد
متورم می‌شد، هیچ راهی برای «درست کردن» آن وجود نداشت و آمار دسته‌ها و خوشه‌های شرط هم آلوده می‌شدند.

### باگ ۳ — گیت با یک شرط فعال می‌شد
`totalLearnedTrades >= 10_000 || forceActiveBeforeWarmup` یعنی یا رسیدن به ۱۰,۰۰۰ **یا** یک کلید
دستی، هر یک به‌تنهایی گیت مسدودسازی را روشن می‌کرد؛ در حالی که قرار بود هر دو شرط لازم باشند.

## ۲. راه‌حل ۱: «دفتر یادگیری» با یادگیری دقیقاً یک‌بار (exactly-once)

```
اثرانگشت معامله = FNV-1a64( tradeId | closedAtMs )        // پایدار، مستقل از سود/زیان
دفتر یادگیری    = مجموعهٔ اثرانگشت‌های یکتا + شمارندهٔ ردیف‌های هرس‌شده
عدد یادگیری      = اندازهٔ دفتر + ردیف‌های هرس‌شده          // همیشه مشتق‌شده، هرگز دستی افزایش نمی‌یابد
```

* `NeuralLearningLedger.tradeFingerprint` هویت معامله را می‌سازد؛ ویرایش سود/زیان معامله، یادگیری
  تازه تولید نمی‌کند.
* پیش از هر گام آموزش، وجود اثرانگشت بررسی می‌شود؛ اگر ثبت شده باشد **هیچ** گام AdamW و هیچ
  به‌روزرسانی خوشه/دسته انجام نمی‌شود.
* دفتر حداکثر ۲۰٬۰۰۰ ردیف زنده نگه می‌دارد؛ ردیف‌های قدیمی «هرس» می‌شوند ولی شمارش‌شان در
  `learnedLedgerPrunedCount` می‌ماند، بنابراین مجموع هرگز اشتباه نمی‌شود.
* آمار برد/باخت هر دستهٔ بازار از همین دفتر بازسازی می‌شود (`normalizeDerivedCounts`).

### مهاجرت بی‌خطر از وضعیت فعلی گوشی شما (بدون از دست دادن آموخته‌ها)
1. پیش از هر تغییر، فایل `neural_self_learning_v1.json` به
   `neural_self_learning_pre_v2_<timestamp>.json` **پشتیبان** می‌شود.
2. همهٔ آموخته‌ها — وزن‌های FT-Attention، شبکهٔ SwiGLU، ممان‌های AdamW، خوشه‌های شرط، پارامترهای
   تیون‌شده و آمار دسته‌ها — **دست‌نخورده** منتقل می‌شوند.
3. دفتر از `replayBuffer` کاشته می‌شود و سپس در اولین همگام‌سازی، تاریخچهٔ ژورنال **فقط در دفتر
   ثبت می‌شود** (`ledgerBackfillPending`)، بدون آموزش دوباره؛ نتیجه: عدد یادگیری = تعداد معاملات
   واقعیِ ژورنال، در حالی که آموزش‌های قبلی دست‌نخورده می‌مانند.
4. تعداد یادگیری‌های تکراری که از شمارنده حذف شده در `duplicatesRepairedCount` و در پنل
   «🧾 دفتر یادگیری» نمایش داده می‌شود و در کارنامهٔ تغییرات هم ثبت می‌شود.

## ۳. راه‌حل ۲: گیت دوشرطی ۱۰,۰۰۰ + اجازهٔ کاربر

```kotlin
val gate = NeuralLearningLedger.gateState(
    learnedTotal = totalLearnedTrades,
    target = warmupTargetTrades,                    // ۱۰٬۰۰۰
    userActivationEnabled = gateUserActivationEnabled,
)
// gate.isGateActive = (learnedTotal >= target) && userActivationEnabled
```

| حالت | نتیجه |
|---|---|
| کمتر از ۱۰,۰۰۰، کلید خاموش | فقط یادگیری + هشدار (فاز یادگیری) |
| کمتر از ۱۰,۰۰۰، کلید روشن | فقط یادگیری؛ کلید شما ثبت شده و پس از ۱۰,۰۰۰ خودکار وارد مدار می‌شود |
| ۱۰,۰۰۰ یا بیشتر، کلید خاموش | **گیت غیرفعال** — «شرط ۱ کامل شد، منتظر اجازهٔ شما» |
| ۱۰,۰۰۰ یا بیشتر، کلید روشن | **گیت فعال** — ورود در شرایط پرخطر مسدود می‌شود |

کلید «شرط ۲» هر زمان قابل خاموش‌کردن است و همان لحظه گیت را غیرفعال می‌کند (حتی بالای ۱۰,۰۰۰).
هیچ‌کدام از دو شرط جای دیگری را نمی‌گیرد.

## ۴. راه‌حل ۳: چطور اصلاحات شبکه را در نسخهٔ بعدی «بفهمیم»؟

بهترین روش فعلی صنعت برای این مسئله سه لایه است و هر سه پیاده شده‌اند:

### الف) کارنامهٔ اصلاحات با متن فارسی (`knowledgeChangeLog`)
هر تغییر معنادار خودکار ثبت می‌شود: زمان، نوع، عنوان فارسی، توضیح عددی دقیق و تعداد معاملاتِ
آموخته‌شده در آن لحظه. انواع ثبت‌شده:

| `kindCode` | معنا |
|---|---|
| `PARAM_TUNE` | تیونینگ خودکار (R:R، بافر ATR حد ضرر، سقف کیجون، حداقل ER، آستانهٔ گیت) با تعداد نمونه |
| `NO_TRADE_DISCOVERED` | کشف شرایط ممنوعه در یک دسته با احتمال برد و میانگین R |
| `LOSS_PATTERN` | الگوی باخت تکرارشونده (سه باخت در یک خوشهٔ شرط) |
| `GATE_USER_ENABLED` / `GATE_USER_DISABLED` | تصمیم شما برای شرط ۲ |
| `SCHEMA_MIGRATION` / `LEDGER_BACKFILLED` | مهاجرت داده و پُرکردن دفتر از تاریخچه |
| `LEDGER_RECONCILED` / `KNOWLEDGE_IMPORTED` | تطبیق دفتر با ژورنال و بازخوانی بستهٔ دانش |

سقف ۱۶۰ رویداد آخر نگه داشته می‌شود و همین فهرست در تب «هوش عصبی» (بخش
«🗂️ آخرین اصلاحات ثبت‌شدهٔ شبکه») دیده می‌شود.

### ب) بستهٔ دانش نسخه‌دار با چک‌سام (`KnowledgeBundle`)
دکمهٔ «🧾 ذخیرهٔ بستهٔ دانش» دو فایل در `Download/AurumEdge/Archive` می‌سازد:

| فایل | محتوا |
|---|---|
| `AurumNeuralKnowledge_v2_<code>.json` | کل وضعیت دانش: وزن‌ها، خوشه‌ها، پارامترها، دفتر یادگیری، کارنامهٔ اصلاحات + `payloadSha256` |
| `AurumNeuralKnowledge_Manifest_FA_<code>.md` | منیفست فارسی خوانا: تعداد معاملات آموخته‌شده، نسخهٔ طرح داده، نسل تیونینگ، وضعیت گیت و جدول کامل اصلاحات |

اعتبارسنجی هنگام بازخوانی: نوع بسته (`bundleKind`)، نسخهٔ طرح (نباید از اپ جدیدتر باشد) و
**چک‌سام SHA-256 محتوا**؛ فایل ناقص یا دست‌کاری‌شده رد می‌شود.

### ج) ادغام ایمن در نسخهٔ بعدی (merge، نه overwrite)
```
دفتر جدید = اتحاد(دفتر فعلی, دفتر بسته)      // هیچ یادگیری‌ای گم یا دوباره شمرده نمی‌شود
وزن‌ها     = اگر adamStepCount بسته ≥ مقدار محلی ⇒ دانش بسته، وگرنه دانش محلی
شرط ۲      = همیشه تصمیم محلی کاربر (از فایل بازخوانی نمی‌شود)
```
بنابراین در نسخهٔ بعدی اپ فقط کافی است بستهٔ دانش را نگه دارید و «📥 بازخوانی بستهٔ دانش» را بزنید؛
هرچه شبکه در نسخهٔ قبل اصلاح کرده بود، هم بازیابی می‌شود و هم با متن فارسی قابل خواندن است.

> **برای انتقال به نسخهٔ بعدی به من (عامل هوش مصنوعی):** فایل
> `AurumNeuralKnowledge_v2_<code>.json` و منیفست `.md` کنار آن را از همان پوشه بفرستید. منیفست
> فارسی، فهرست کامل اصلاحات و اعداد را می‌دهد و JSON برای بازسازی/مقایسه/مهاجرت قابل استفاده است.
