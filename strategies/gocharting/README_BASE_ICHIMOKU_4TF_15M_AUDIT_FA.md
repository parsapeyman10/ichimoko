# اسکریپت بازبینی `BASE_ICHIMOKU` برای GoCharting / Lipi v2

فایل [`BASE_ICHIMOKU_4TF_15m_Audit.lipi`](BASE_ICHIMOKU_4TF_15m_Audit.lipi) یک **strategy تشخیصی و بک‌تست تاریخی** است. هدف آن پیدا کردن محل دقیق تصمیم‌های مدل خالص چهارمکتبی `BASE_ICHIMOKU` روی چارت است؛ سفارش واقعی به صرافی، Binance یا حساب کاربر ارسال نمی‌کند.

این انتقال از مسیر BASE مرجع `f1c9850ae290bbbc5e953c8fdf453c05754928cd` تهیه شده است. مسیرهای `Hidden Cross`، `Parsa`، `BTC-52`، `Peyman` و `NeoWave` عمداً در آن نیستند.

> **برای خطای `Execution timed out` از نسخهٔ سبک استفاده کنید:**
> [`BASE_ICHIMOKU_15m_30m_1h_Light_Audit.lipi`](BASE_ICHIMOKU_15m_30m_1h_Light_Audit.lipi).
> این نسخه فقط `15m → 30m → 1H` را با bucketهای کاملاً بسته بازسازی می‌کند و برای GoCharting بسیار سبک‌تر است. حدود **۳ روز تاریخچهٔ 15m** (57 کندل 1H بسته) برای warm-up آن کافی است. به‌علت حذف 4H، هم‌ارز بیت‌به‌بیت مدل مرجع 4H/1H/15m نیست. قبل از افزودن آن، اسکریپت 4TF قدیمی را از چارت حذف کنید تا هم‌زمان اجرا نشوند.

## افزودن به GoCharting

1. در GoCharting یک نماد با کندل‌های پیوسته باز کنید.
2. interval را دقیقاً روی **`15m`** بگذارید. اسکریپت روی 1H، 4H، Renko، Range و intervalهای دیگر دادهٔ لازم را ندارد و در جدول گوشهٔ چارت پیام `CHANGE TO 15m` نشان می‌دهد.
3. timezone چارت/داده را **UTC** بگذارید و به اندازهٔ کافی تاریخچه بارگذاری کنید. حداقل حدود **950 کندل 15m** لازم است تا 57 کندل کاملاً بستهٔ 4H برای warm-up داشته باشیم؛ بیشتر بهتر است.
4. Script Editor را باز کنید، کل فایل `.lipi` را paste کنید، ذخیره و به چارت اضافه کنید.
5. ابتدا جدول `BASE 4TF audit` را کنترل کنید: باید `15m OK` و سپس `READY / LONG` یا `READY / SHORT` دیده شود. تا پیش از آن `WARM-UP` طبیعی است.

اگر editor نسخهٔ جدید Lipi خطایی داد، متن خطا و نام/interval نماد را همراه یک screenshot بفرستید؛ این محیط به GoCharting متصل نیست و نمی‌تواند فایل را آن‌جا compile یا اجرا کند.

## بازسازی بدون look-ahead

Lipi v2 دادهٔ timeframe دیگر را مستقیم درخواست نمی‌کند، بنابراین این اسکریپت فقط از کندل‌های تأییدشدهٔ چارت 15 دقیقه‌ای استفاده می‌کند:

- یک 1H فقط پس از بسته‌شدن چهار کندل UTC در `:00`, `:15`, `:30`, `:45` به آرایهٔ 1H افزوده می‌شود.
- یک 4H فقط پس از بسته‌شدن شانزده کندل UTC از `00:00` تا `03:45` (و bucketهای بعدی) افزوده می‌شود.
- اگر تاریخچه از وسط bucket شروع شود، آن bucket عمداً دور انداخته می‌شود؛ نیمه‌کاره به‌عنوان 1H/4H جا نمی‌زند.
- تا پایان همان کندل 15m، HTF تازه‌ساخته‌شده وارد snapshot نمی‌شود. هیچ کندل 1H/4H در حال ساخت یا کندل آینده در شرط‌ها مصرف نمی‌شود.

نگاشت چهار timeframe این مدل همان `4H (macro) → 1H (strategy) → 15m (trigger)` است. نام «4TF» به مدل مرجع اشاره می‌کند؛ در این نسخهٔ قابل اجرا روی چارت 15m، سه timeframeٔ OHLC موجود به‌صورت بسته‌شده استفاده می‌شوند.

## آنچه روی چارت می‌بینید

| نشانه | معنی |
|---|---|
| `BASE L` مثلث سبز | سیگنال long روی close کندل. سفارش شبیه‌سازی‌شده در open کندل بعدی قرار می‌گیرد. |
| `BASE S` مثلث قرمز | سیگنال short با همان قرارداد next-open. |
| الماس `RAW` آبی | یکی از چهار trigger شکل گرفته ولی gate کامل BASE آن را رد کرده است؛ **معاملهٔ معتبر BASE نیست**. |
| `WAIT` زرد | vetoهای سخت جهت‌دار برقرارند، ولی هنوز هیچ triggerی شکل نگرفته است. |
| `DBG L/DBG S` آبی | فقط وقتی گزینهٔ `DEBUG ONLY: simulate raw trigger candidates` فعال باشد، معاملهٔ مجازی برای یک RAW trigger است؛ آن را با BASE اشتباه نگیرید. |
| label سبز/قرمز/آبی | trigger (`KATANA`/`PULLBACK`/`BREAKOUT`/`SANYAKU`)، تعداد شرط‌های پاس‌شده، درصد gate، R:R، SL و TP طرح را نگه می‌دارد. |
| دایرهٔ `V` | trigger شکل گرفته اما یکی از vetoهای سخت BASE رد شده است. |
| ضربدر `C17` | نسبت هزینه به ریسک شرط 17 را رد کرده است. |
| label خاکستری `REJECT` | برای triggerهای ردشده، نخستین blocker و فهرست همهٔ شماره‌شرط‌های ناموفق را نشان می‌دهد. |
| جدول بالا-راست | آماده بودن داده، جهت، تعداد candleهای HTF بسته، درصد سه لایهٔ gate، trigger و وضعیت آخر را نشان می‌دهد. |
| خطوط | Tenkan/Kijun و Kumo 15m، Kijun ساخته‌شدهٔ 1H/4H و در معاملهٔ باز SL/TP. |

اعداد `C1` تا `C17` همان 17 شرط BASE هستند. `Book gate` شامل vetoهای سخت `1/3/4/6/17`، وزن‌های quality و trigger و شمارش دوبارهٔ وزن 17 در دو لایه است؛ در حالت پیش‌فرض maximum-execution، quality و trigger حداقل 60٪ و مجموع حداقل 70٪ می‌خواهند.

### اگر بخش Strategy صفر معامله دارد

اول به markerها نگاه کنید، نه فقط Strategy Tester:

1. `WARM-UP` یعنی دادهٔ 4H بستهٔ کافی ندارید؛ حداقل حدود 950 کندل 15m بارگذاری کنید.
2. `WAIT` یعنی جهت و vetoهای سخت برقرارند اما trigger رخ نداده است.
3. `RAW` یا `REJECT` یعنی trigger رخ داده اما شماره‌شرط‌های موجود در label علت رد را نشان می‌دهد.
4. برای دیدن معاملهٔ شبیه‌سازی‌شده روی تمام `RAW`ها، در تنظیمات اسکریپت فقط برای عیب‌یابی گزینهٔ **`DEBUG ONLY: simulate raw trigger candidates`** را فعال کنید. معامله‌های آبی `DBG` عمداً استاندارد BASE نیستند و نباید برای ارزیابی سودآوری استفاده شوند.

## دامنهٔ منطق منتقل‌شده

اسکریپت شامل این بخش‌هاست:

- snapshots ایچیموکو با `9/26/52/26`، Chikou، Kumo جاری/آینده، ATR14، flat SSB/Kijun، ER14، wick/body/volume، fractal، Kijun30 و EMA34؛
- انتخاب جهت BASE و 17 شرط شامل Sanyaku، Chikou، Kumo، هزینه، sniper distance و `bookConfluenceGate`؛
- triggerهای `EARLY_KATANA_GENESIS`، `PULLBACK_BOUNCE`، `VALIDATED_BREAKOUT` و `SANYAKU_TK_CONTINUATION`؛
- موج Hosoda، چرخهٔ زمانی، targetهای `NT/V/N/E` و دیوارهای flat Kijun/SSB؛
- اولویت حدضرر چهارمکتبی: Kijun26، Kijun30/EMA34، fractal، لبهٔ Kumo و نقطهٔ S موج؛ سپس corridor و R:R محافظت‌شدهٔ 1.5 تا 3R؛
- ورود شبیه‌سازی‌شدهٔ next-open، bracket SL/TP و time stop قابل تنظیم.

برای ظرفیت Lipi، plateauهای نزدیک در این فایل از سطح‌های flat خام 1H/4H گرفته می‌شوند؛ merge کامل لیست plateauهای Android و tick rounding اختصاصی venue در اینجا وجود ندارد. این دو مورد، به‌علاوهٔ نبود مسیر tick/sniper زنده و تفاوت order emulator GoCharting، یعنی نباید نتیجه را parity بیت‌به‌بیت با Android یا سودآوری/معاملهٔ واقعی تلقی کرد.

## هزینه و تنظیمات مهم

`Round-trip execution cost fraction` به‌طور پیش‌فرض `0.0021` است: 10bp fee در هر سمت + 1bp spread رفت‌وبرگشت، که با رفتار مرجع برای جفت‌های **USDT/crypto** (از جمله طبقه‌بندی مرجع `XAUUSDT`) سازگار است. برای `XAUUSD`، Forex یا broker دیگر باید مقدار cost را به هزینهٔ واقعی همان نماد تغییر دهید. `commission_value=0.105` در strategy نیز تنها تقریب همین هزینه برای گزارش بک‌تست است.

پارامترهای quantity، هزینه، ATR-extension، SL buffer، ER/volume/wick و time stop در تنظیمات Lipi قابل تغییرند. تغییر آن‌ها دیگر مقایسهٔ خالص با تنظیمات BASE مرجع نیست.

> هشدار: این ابزار توصیهٔ سرمایه‌گذاری نیست. بک‌تست و markerهای آن برای visual debugging هستند، نه مجوز اجرای معاملهٔ واقعی.
